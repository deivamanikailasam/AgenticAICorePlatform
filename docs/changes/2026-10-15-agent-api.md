# A run API that a web page can drive: live events, approvals, cancel

**Step:** 17 · **Commit:** feat(agent-api): add the run API with AG-UI streaming and approvals · **Date:** 2026-10-15

## What changed
A new service, `agent-api` (port 8091, bound to 127.0.0.1, hardened container), with:
- create a run (an `Idempotency-Key` with the same request returns the same run; with a
  different request it is refused), get its state, cancel it, list your threads;
- stream its events as **AG-UI** (an open protocol for agent user interfaces) over SSE, or over a
  WebSocket: text as the model writes it, every tool call with its arguments and result, each
  step, state changes, and a `RUN_FINISHED` with an `interrupt` that names the proposed action
  when a person must approve. Events are numbered; reconnecting with `after=<last number>` misses
  nothing;
- approve or reject as **the caller**: the approver's username and groups come from their
  verified Keycloak token, never from the request body. The requester cannot approve their own
  run, people outside the approver group cannot see it, and the generic resume cannot be used to
  answer an approval;
- a minimal page at `/` that runs an agent, shows live tool calls and the answer, and offers
  Approve / Reject, using only AG-UI events. Tokens travel in headers (the WebSocket takes its
  token in the first message), never in URLs; the page sets a strict Content Security Policy.
- Every call needs a token verified against Keycloak (issuer, signature, expiry, audience).
  Tool calls run as the requesting user under OPA (or Cerbos) and are audited.
- Stand-in stack: a test approver (`jo`, in `/acme/approvers` and `/acme/finance-approvers`).
- Development dependency: `playwright==1.63.0` (released 2026-09-15; cooldown rule, ADR 0022)
  for the browser test; runtime dependency `ag-ui-protocol==1.0.0` (2026-09-17).

## Why
Step 17: agents need an API that applications and people can use, with streaming so users see
progress, and approvals that cannot be faked by whoever holds the request.

## How to check it
- `uv run pytest services/agent-api` — 9 passed: token required; AG-UI stream contents up to the
  approval interrupt; approval from the approver's token (self-approval 403, outsider 404,
  body field ignored); rejection pays nothing; idempotent creation; tenant isolation; resume
  cannot answer an approval; cancel; WebSocket; the page.
- With the stand-in stack: `uv run pytest -m integration services/agent-api` — the invoice-triage
  agent runs through the real service with Keycloak tokens and OPA; headless Chromium drives the
  page from start to approval to payment.

## Risks and follow-ups
Runs live in memory until Step 18 (a restart loses them). After an approval the run continues
with the requester's token, which can expire on long waits; delegated long-lived credentials are
Step 29. Two people approving, edits and expiry are Step 28.
