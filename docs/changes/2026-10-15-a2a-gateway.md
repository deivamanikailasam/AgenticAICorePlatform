# A2A gateway: publish agents with signed Agent Cards

**Step:** 24 · **Commit:** feat(a2a-gateway): publish agents over A2A with signed cards, Keycloak and OPA · **Date:** 2026-10-15

## What changed
- New service `services/a2a-gateway`, on `127.0.0.1:8092` in compose. It serves every agent
  whose spec sets `interop.a2a_publish: true`. Today that is `hello-workflow`.
- For each published agent, the gateway serves:
  - the Agent Card, signed ES256 with the platform key from the secret store;
  - a JSON-RPC endpoint and an HTTP+JSON endpoint;
  - optionally gRPC, for one agent on its own port.
- Every call except fetching the card goes through the same gate:
  - a missing or invalid Keycloak token gets 401;
  - OPA then decides `a2a.inbound`, and a denial gets 403. The decision is audited.
  - an agent that is not published gets 404.
- The gRPC binding uses the same gate (UNAUTHENTICATED / PERMISSION_DENIED).
- A task runs through the run API with the caller's own token, so identity, grants, approvals
  and audit are the same as for any client. Run results map to A2A task states:
  - success → completed, with the answer as an artifact;
  - waiting for approval or input → input-required;
  - failure or stop → failed.
- Push notifications go only to hosts in `a2a.publish.push_allowed_hosts`, over HTTPS. Plain
  HTTP is allowed only to loopback.
- OPA (`policies/agent/tools/decision.rego`, version 2026-10-15.4): the agents' kill switch now
  also covers `a2a.inbound`. Four new rego tests cover allow, an unpublished agent, an
  unauthenticated caller and the kill switch.

## Why
Step 24's "Done when": an agent built with a different framework calls a Project A agent over
A2A, and the reverse; an unsigned or unlisted remote agent is refused. The gateway adds no
second policy path. It authenticates the caller, asks OPA once, and hands the work to the run
API, where every tool call is still checked one by one.

## How to check it
`uv run pytest services/a2a-gateway/tests && just policy-test`

The tests cover:
- a Pydantic AI agent (FunctionModel) calls `capital-desk` through the gateway and gets
  "Canberra.";
- a Project A agent calls a Pydantic AI agent served with `a2a-sdk` as `a2a://pyd-helper`. Its
  hostile reply comes back as data, and the call is audited with OPA's decision;
- a card checked against the wrong key is refused;
- 401, 403 and 404 cases, plus the push URL allowlist;
- gRPC allowed and denied.

## Risks and follow-ups
- Task state is in memory (`InMemoryTaskStore`), so a gateway restart loses in-flight A2A task
  ids. The runs themselves are durable in agent-api. The SDK's `DatabaseTaskStore` is the
  upgrade path.
- VERIFY-ON-MAC: run `just up`, then fetch
  `http://127.0.0.1:8092/agents/hello-workflow/.well-known/agent-card.json` with a real Keycloak
  token and `A2A_SIGNING_KEY_DEV` set.
